## 0. 现状基线（第二阶段末实测）

- **全量 571 passed** / ruff+mypy+bandit 全绿 / v3.2.0 已发布
- **26 个 Web 模板交互深度盘点**：只有 student_list.html 有完整 CRUD（9 按钮），
  其余 25 个页签：`class_list`(0)/`classroom_list`(0)/`teacher_list`(0)/`exam_manage`(0)/`score_entry`(1)/
  `semester`(1)/`student_register`(2)/`exam_rooms`(2)/`users`(2) 等，绝大多数是**只读查询**。
- 链路抽测证明后端 API 大体完备（学生 CRUD 已补全为模板），**瓶颈在前端缺操作 UI + 部分后端缺写接口**。

## 1. 第三阶段目标（一句话）

> **把 Web 端从"功能浏览器"打磨成"可日常使用的操作台"**：核心业务页签（学生/成绩/考试/班级/教师）全部支持增删改查 + 导入导出，桌面端能力 Web 端可替代。

## 2. 核心原则（沿用既有）

- 复用：优先复用现有 API/服务层，缺写接口才补后端，绝不重复造轮子
- 零代码扩展：新页面尽量复用 ui_config 驱动的渲染模式
- 每页签 = 前端 UI + 契约测试 + 浏览器实测，完成即 commit
- TDD：先写契约测试（RED）→ 补后端 → 前端接入（GREEN）

## 3. 开发规划（按价值排序）

### P3-A 高频操作页签补齐 CRUD（最高价值，★★★）

> 教务日常最高频的操作页签，Web 端必须可替代桌面。每项含：列表查询✅（已有）+ 新增/编辑/删除 + 表单校验。

| 任务 | 页签 | 现状 | 要补的 | 验收 |
|------|------|------|--------|------|
| A1 | 班级管理 class_list | 只读 | CRUD + 班级下拉复用 /api/class | 增删改班级浏览器实测 |
| A2 | 教师管理 teacher_list | 只读 | CRUD + 任课分配 | 增删改教师实测 |
| A3 | 考试成绩录入 score_entry | 仅录入 | 编辑/删除/发布/锁定 + Excel 导入 | 录入+发布+锁定闭环 |
| A4 | 考试管理 exam_manage | 只读 | CRUD + 考场/监考/准考证联动 | 建考试→分考场→准考证闭环 |
| A5 | 教室管理 classroom_list | 只读 | CRUD | 增删改教室实测 |
| A6 | 学期管理 semester | 只读 | 新建/继承/锁定 | 四色继承预览 + 锁定实测 |

### P3-B 全局能力 Web 化（★★★）

## 4. 执行顺序（依赖驱动）

```
P3-A1/A2（班级/教师 CRUD，后端/API 已基本就绪）→ A3/A4（成绩/考试，最复杂）
→ A5/A6 → P3-B（全局能力，依赖 A 组的写接口模式）→ P3-C（联动）→ P3-D（验收）
```

## 5. 每页签完成标准（DoD）

1. 后端写接口存在（POST/PUT/DELETE）且有契约测试
2. 前端有新增/编辑/删除 UI + 表单校验 + 错误提示
3. 浏览器实测：增→查→改→删 全链路 200
4. ruff/format 干净 + 全量测试不降
5. 提交 + push
